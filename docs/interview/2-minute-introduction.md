# 两分钟中文项目介绍

我做的项目叫 RepoMind，是一个面向 Java 和 Python 仓库的代码理解与故障调查工具。它不是把整个仓库塞给大模型聊天，而是先用 tree-sitter 建 Symbol 索引和调用关系，再让本地 Qwen2.5-Coder Agent 按问题一步步调用搜索、调用方/被调用方和源码读取工具。

这个项目最难的地方其实不是把模型接上，而是让结论可信。早期真实测试里，Agent 会反复搜索同一个 Symbol，甚至耗尽工具步数；模型有时还会给出没有源码支持的行号、调用链，或者在价格问题里直接猜“正确公式”。我后来加了执行状态和重复调用拦截，让每一步都记录有没有拿到新证据；再用 Verified Evidence Store 和最终诊断校验，把源码事实与模型推断分开。调用链则只沿 AST 已解析边做有界路径查找，并明确标注它只是静态路径。

我用固定的 8 个场景做了真实 Ollama 回归。最初是 3 个 PARTIAL、3 个 FAIL、2 个 UNSUPPORTED；执行策略后变成 6 个 PARTIAL、0 个 FAIL、2 个 UNSUPPORTED。平均工具步数从 6.62 降到 5.12，重复调用尝试从 7 次降到 1 次。这个数字不是通用准确率，只能说明在这组场景里的行为更稳定。

我也刻意保留了限制：比如没有业务需求就不能证明正确的计价公式，当前也不能分析 YAML 配置；静态调用图更不能证明运行时一定走了那条路径。对我来说，这个项目最大的收获是：Agent 的可靠性要靠确定性的代码分析、证据来源和校验机制，而不只是把 Prompt 写得更强。
