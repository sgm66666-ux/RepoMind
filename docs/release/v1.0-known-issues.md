# RepoMind v1.0 已知限制

- Java/Python CALLS 是保守静态解析；Python 动态分派、复杂别名、反射、多态与跨语言调用可能未解析。CallPathFinder 只沿已解析边给出最短静态路径，不能证明运行时实际执行。
- 索引保存在 FastAPI 进程内存中；重启后必须重新分析仓库。同一进程只有一个当前仓库，切换 Demo 会替换索引；不要并发切换仓库并运行 Agent。
- YAML/properties 配置值与代码使用位置尚不能关联，相关问题返回 UNSUPPORTED，不能作为成功定位。
- 没有需求或测试说明时，源码只能证明当前公式，不能证明正确业务规则。v1.0 补强了对“修正价格计算公式为 …”的校验；旧冻结报告保留此前出现过的过度修复建议。
- 本地 `qwen2.5-coder:14b` 可能给出错误行号、不充分的不确定性或无法核验的源码文字；Projection/Validation 只能去除已覆盖的模式，最终推断仍需人工核对。
- 本次 Register Demo 的静态图路径来自 3 条 AST 已解析边，但 Agent 只调用了两次 `searchSymbol`，没有读取路径中间方法的源码；FinalDiagnosis 的不确定性/修复建议字段为空，图路径也不能说明运行时执行。
- Agent 可能因模型输出格式、超时或 Ollama 负载失败；`/health` 仅代表服务进程存活，不能证明 LLM 持续可用。
- 8 场景基准规模小且特定于 Demo；6 PARTIAL / 2 UNSUPPORTED 不代表通用准确率或生产可用 SLA。最新运行中 `business-order-return` 的调用链匹配较前版退步。
- 前端构建有大 chunk 警告；构建成功，但尚未做进一步拆包优化。
